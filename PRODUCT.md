# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

HTML and CSS only; static front-end hosted on GitHub Pages.

## Users

University instructors evaluating a web programming assignment. The portfolio owner is an information technology student.

## Product Purpose

A personal portfolio that introduces the student and presents their work for academic evaluation. Success means instructors can quickly understand who the student is, review their work, and find the student's contact and profile links.

## Capabilities and Constraints

- Static front-end only; use HTML and CSS without a framework, imported library, back end, or unnecessary tooling.
- Keep the source easy for a student to read and analyze.
- Personal details and links not supplied by the student must remain clearly editable placeholders. The student supplied the device models, study details, skills, and current project title used on the relevant pages.
- The target hosting platform is GitHub Pages.
- The portfolio should include an introduction, programming skills, education level, devices used, projects in development, and contact options for Facebook, Zalo, and email.
- The student approved the dark, handwritten multi-page direction before implementation; do not make further unrequested visual decisions.

## Evidence on Hand

- Devices: iPhone 16 Plus and Redmi Book Pro 14S.
- Portfolio owner: Nguyễn Viết Tâm. Portfolio year: 2026.
- Study details: IELTS 5.0, HSK 3, two Roblox game projects, Pro Blender, and the goal “Cố gắng đạt bằng khá”.
- Programming skills to show: HTML - CSS, JavaScript, and LUA.
- Current project title: Chatbot AI của Trường Đại học Đại Nam. The student will provide its description.
- No device or project imagery, biography, or social URLs have been provided. Do not invent them. Keep the two device-image slots, project media, and project/contact destinations as empty `src`/`href` examples with prominent Vietnamese HTML comments. Other sections need no evidence links or images.

## Product Principles

- Make the student's work and identity easy to understand.
- Keep the implementation small, semantic, and approachable to analyze.
- Use only verified personal information; make missing material explicit and easy to replace.
- Get approval for the interface direction before implementation.
